* Overview
:PROPERTIES:
:CUSTOM_ID: overview
:END:

Monarch is a distributed programming framework for PyTorch built on the
*hyperactor* actor system. The Rust layer provides a single =cdylib= Python
extension, PyO3 bindings to the actor framework, a PyTorch tensor worker actor,
NCCL/RDMA communication, and FFI to libtorch/CUDA/NCCL.

** Scale

| Layer                                             | Crates | LoC     |
|---------------------------------------------------+--------+---------|
| Foundation (typeuri, wirevalue, ndslice, etc.)    |     12 | ~35,700 |
| Actor Framework (hyperactor, hyperactor\_mesh)    |      2 | ~52,500 |
| Application (monarch\_*, torch-sys, nccl-sys)     |     15 | ~47,000 |
| Macros (hyperactor\_macros, config\_macros, etc.) |      6 | ~3,600  |
| *Total*                                             |     *39* | *~135k*   |

** Architecture

#+BEGIN_EXAMPLE
Host (frontend mux — multi-proc)
  └── Proc (actor runtime — owns actor lifecycle)
       ├── MailboxMuxer (routes to local actors)
       ├── Forwarder (routes to remote procs via channels)
       ├── Instance<A> (running actor context)
       │    ├── Mailbox (typed ports + message delivery)
       │    ├── InstanceCell (shared: status, handlers, introspect)
       │    ├── Sequencer (per-session message ordering)
       │    └── ActorLocalStorage (per-actor TLS analog)
       └── Supervision hierarchy (parent → child events)
#+END_EXAMPLE

*** Key Methods

- =Proc::local()= — thread-local proc with =PanickingMailboxSender=
- =Proc::configured(proc_id, forwarder)= — production proc with routing
- =Proc::spawn<A: Actor>(name, actor)= — spawn root actor
- =Proc::spawn_child<A>(parent, actor)= — spawn supervised child
- =Proc::post(envelope, return_handle)= — route message
- =Proc::serve(rx)= — start receiving from channel
- =Proc::destroy_and_wait(timeout, reason)= — graceful shutdown

*** Server Loop

1. Initialize actor via =actor.init()=
2. Loop: receive from unbounded work queue → dispatch → update status
3. Handle signals (=DrainAndStop=, =Stop=, =Abort=, =ChildStopped=)
4. On termination: =actor.cleanup()=, notify supervision coordinator
5. Panics caught via =AssertUnwindSafe= + =catch_unwind= with backtrace capture

*** Concurrency

- =DashMap= for concurrent actor registration/lookup
- =AtomicUsize= for ID allocation
- =watch::channel= for status observation
- =tokio::spawn= per actor with panic catching

*** Port System

| Type                | Purpose                              |
|---------------------+--------------------------------------|
| =PortHandle<M>=     | Local handle for sending typed msgs  |
| =OncePortHandle<M>= | One-shot send handle                 |
| =PortReceiver<M>=   | Local receiver for typed msgs        |
| =OncePortReceiver<M>= | One-shot receiver                  |
| =PortSink=          | =futures::Sink= adapter for streaming |

Ports are typed endpoints within a mailbox. Each port gets a unique index
(allocated atomically). Actor ports use a high bit (=ACTOR_PORT_BIT=) to
distinguish from user ports.

*** Delivery Chain

#+BEGIN_EXAMPLE
PortRef.send()
  → context::post()
    → MailboxSender.post_unchecked()
      → route (local muxer OR channel dial)
        → destination Proc.post()
          → MailboxMuxer
            → OrderedSender
              → work queue
                → Handler::handle()
#+END_EXAMPLE

** Error Handling Patterns

- *Handler errors*: =anyhow::Error= propagated as =ActorErrorKind::Generic=
- *Typed errors*: =thiserror::Error= derive throughout (=ChannelError=, =MailboxError=, =mesh::Error=)
- *Mesh errors*: 19-variant enum with =Box= wrapping of large inner types
- *FFI errors*: =From= impls wrap bincode, serde_json, base64, allocator, channel errors
- *Concern*: ~1,200+ =.unwrap()= in =hyperactor/src/= non-test code

** Notable Design Decisions

1. *Tagless-final =Selection=* in ndslice — enables multiple interpretations from one algebra
2. *=inventory= crate everywhere* — linker-level registration for types, config keys, reducers
3. *=min_specialization= in serde_multipart* — =Part= serializes differently per backend
4. *GIL serialization* — =tokio::sync::Mutex= with re-entrancy detection via thread-local depth
5. *=format!().leak()=* for type name interning — bounded but technically a leak
6. *Cooperative preemption* (=preempt_rwlock=) — readers watch for writer pressure and yield
7. *Dual cast paths* (v0/v1) — =CommActor= tree vs direct per-actor send
